# 설정 가이드

## 역할 나누기

Stream Deck Mobile은 모바일 기기의 버튼 화면을 제공하고, 연결된 컴퓨터의 Stream Deck 앱이 프로필과 동작을 관리합니다. 자동화 스크립트나 플러그인이 필요하면 해당 컴퓨터에서 동작합니다. 실제 지원 버전과 연결 조건은 [Elgato의 안내](https://help.elgato.com/hc/en-us/articles/16786832942221-Elgato-Stream-Deck-Mobile-2-0-Getting-Started)를 확인합니다.

이 저장소에는 사용 중인 프로필의 복제본이나 장치를 제어하는 실행기가 없습니다. 예시는 구성과 검증 방법을 설명하기 위한 출발점입니다.

## 버튼 하나를 추가하는 순서

1. 현재 프로필을 앱의 내보내기 기능으로 백업하고 저장소 밖의 비공개 위치에 보관합니다.
2. 버튼의 목적과 기대 결과를 한 문장으로 적습니다. 예: 공개 문서 페이지를 한 번 엽니다.
3. 이미 설치된 기능으로 가능한지 확인합니다. 플러그인 설치, 접근 권한, 계정 연결을 임의로 늘리지 않습니다.
4. 기존 버튼을 덮어쓰지 않고 빈 위치나 복제한 테스트용 프로필에서 버튼 하나를 설정합니다.
5. 한 번 누름, 연속 누름, 연결 끊김, 대상 앱이 열려 있지 않은 경우를 각각 확인합니다.
6. 문제가 생기면 추가한 버튼을 제거하거나 비공개 백업에서 이전 설정을 복원합니다.

## 구성 기록 예시

`examples/buttons.example.json`의 필드는 문서화를 위한 형식입니다.

- `id`: 예시 안에서 버튼을 구분하는 이름
- `title`: 버튼의 표시 이름 제안
- `kind`: `open-url`, `launch-app`, `plan-only`처럼 목적을 설명하는 분류
- `enabled`: 예시에서는 항상 `false`
- `target`: 예약 도메인이나 `LOCAL_ONLY` 같은 비실행 자리표시자
- `notes`: 적용 전 확인할 조건

배치 위치와 아이콘은 기기의 화면과 사용자 설정에 맞춰 정합니다. 이 JSON은 Stream Deck의 네이티브 프로필 형식이 아니며 자동으로 적용되지 않습니다.

## 자동화 예시를 늘릴 때

동작의 판정 부분과 실제 실행 부분을 분리하면 장치 없이도 많은 조건을 테스트할 수 있습니다. 모의 테스트에는 가짜 주소, 가짜 상태, 가짜 식별자만 사용합니다.

- URL 열기: 공개 URL인지, 중복으로 열리지 않는지 확인합니다.
- 앱 실행: 정확한 대상과 로컬 경로를 개인 환경에서 확인합니다. 공개 예시에는 실제 사용자 경로를 넣지 않습니다.
- 상태 변경 작업: 현재 상태를 먼저 확인하고, 결과가 불명이면 즉시 반복 실행하지 않습니다.
- 인증이 필요한 작업: 비밀번호, 세션, 토큰을 저장소나 로그에 넣지 않습니다. 추가 권한이나 본인 확인이 필요한 단계는 사용자가 검토하고 완료하도록 둡니다.

VPN 판정 예시는 이런 분리의 한 사례입니다. 실제 서비스의 로그인 화면이나 보안 검사를 자동화하는 코드는 포함하지 않습니다.

## 검증 결과 구분

모의 테스트 통과는 합성 입력에 대한 코드의 판단만 확인합니다. 실제 Mobile 버튼 입력, 컴퓨터 연결, 대상 앱 동작은 장치에서 별도로 확인합니다. 검증 기록을 공개할 때는 장치 이름, 회사 정보, 계정, 화면의 민감한 내용을 먼저 제거합니다.
