# 공개 전 확인

공개 저장소의 파일, 커밋 기록, 이슈, CI 로그와 첨부 파일은 누구나 볼 수 있습니다. 다음 사항을 확인한 파일만 추가합니다.

## 포함해도 되는 예시

- 새로 작성한 일반적인 설정 설명
- 예약 도메인과 합성 식별자를 사용하는 설정 예시
- 개인 환경에 연결되지 않는 모의 코드와 테스트
- 비밀값이 필요 없는 검증 명령과 CI 초안

## 포함하지 않는 것

- 실제 계정, 이메일 주소, 회사 도메인, 내부 URL 또는 호스트 이름
- 비밀번호, 인증서의 개인키, API 키, 토큰, 쿠키, 복구 코드
- 실제 프로필과 백업, 사용자 경로, 기기 식별자
- 로그인 페이지의 HTML이나 계정 정보가 보이는 화면 캡처
- 개인 작업 기록, 대화, 승인 기록, 원본 테스트 로그
- 회사 내부 시스템에 접속하거나 보안 검사를 건너뛰는 실행 코드

## 변경마다 확인할 것

1. 추가하거나 수정한 파일의 전체 내용을 읽습니다. `.gitignore`는 이미 추적된 파일이나 비밀값을 안전하게 만들어 주지 않습니다.
2. 주소, 경로, 식별자가 합성 예시인지 확인합니다. 실제 값에서 일부 글자만 가리는 것보다 처음부터 가짜 예시를 만드는 편이 안전합니다.
3. 실행 명령과 CI가 비밀값이나 실제 계정 없이 동작하는지 확인합니다.
4. 모의 테스트와 실제 장치 검증 결과를 구분합니다. 실행하지 않은 검사를 통과했다고 적지 않습니다.
5. 공개할 파일 목록과 diff를 확인한 뒤 해당 파일만 선택해 커밋합니다.

민감한 값이 공개됐다면 파일 삭제만으로 해결됐다고 보지 않습니다. 해당 서비스에서 자격증명을 폐기하거나 갱신하고, Git 기록·로그·캐시 등에 남았는지 별도로 대응해야 합니다.
